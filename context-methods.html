Ways to work with more context

Compare what each approach keeps, what it costs and what the experiments showed.

Files, summaries and self-editing can keep a task going beyond one context window. They do it by controlling what stays in view. A larger window holds more at once; a prefix cache avoids repeated reading. Neither creates unlimited memory.

“Decode” means generating the answer, measured in output tokens per second. Total task time also includes reading, tool calls, searches, summaries and retries.

What worked best in this experiment?

The task was a running ledger: process 20 batches of updates, then report 24 current values. The 121K tokens of input contained much more text than the small table needed to answer. That made it a good task for code and external files.

StrategyCorrect / 24Elapsed time
Large window, exact cache on2426 min
Summarise at 75% of the budget2441 min
Self-editing, files allowed241.9 min
No management, files allowed241.9 min

The two file-using agents both got 24/24 in about 1.9 minutes. The big-window and summary agents also got 24/24, taking about 26 and 41 minutes. These are elapsed times for one ledger trial, not universal speed multipliers or measurements of disk write overhead.

Can any of these remember everything forever?

No finite context can hold every detail of an ever-growing history. Files can retain an archive up to available storage; retrieval decides what to read. A summary or state table can support a long task when it preserves everything that task needs. If future questions may require arbitrary original details, retain the originals too.

The completed 121K-token task exceeded the small 32K budget, but still fit inside the model’s 262K maximum. It demonstrates working with a smaller context; it is not a completed demonstration of an endless task.

Other approaches: retrieval, rolling windows and compression

Retrieval-augmented generation (RAG) selects passages from an external collection. File search is a simple version of the same idea; this ledger used code and files, not a separately benchmarked vector database. A rolling window discards old text, and a model-written summary can omit details. Both can keep a session moving while losing information. Reducing the precision of the numerical cache saves memory but changes its numbers; that was not part of these context experiments.

Recursive reading of documents and selective cache eviction are related approaches, not measured competitors in the ledger table. Follow the research review for the wider literature.
