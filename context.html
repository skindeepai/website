Working past the context limit

Which ways of managing an AI’s memory actually helped?

How can an AI keep working on one long job when its history no longer fits in its working memory? The same Qwen3.8-27B model ran each test below; within a test, every approach answered the same questions.

The most reliable approach so far keeps a small, pinned state in view and moves old text, word for word, to an archive the model can search. Approaches that only drop or summarise old text forget the distant past, or report old values as current.

Recommendations

What we would do today when building an agent whose history outgrows its window:

  1. Keep the rules and the goal pinned at the top of the context, so no clean-up step can remove them. Outside studies found that a pinned head was the only compaction that kept rules intact.
  2. Put shared instructions in the system message and keep them unchanged, so the prefix cache can reuse them: a repeated 30K prompt started answering in 0.8 seconds instead of 11.4. How prefix caching works.
  3. Never summarise a summary. Outside studies find each round drifts further from the original, and summarising was the slowest method we ran. Keep the originals. What summaries keep and lose.
  4. Drop tool output whose effect already lives in the environment, but keep the verbatim text searchable in an archive with a search tool. Dropping it outright lost every “who did it” detail. Archive and search versus compaction.
  5. Give a method that edits inside the window at least 32K tokens of room. At 16K the batch, the state, the instructions and the thinking did not fit, and accuracy collapsed.
  6. Measure with questions planted at known distances back, not only end-of-run questions. Final-question scores alone hide stale state: one method scored 13/15 on the planted questions and then 4/14 on the final ones. The distance tables.

What we are trying to solve now

An agent that works on one task for weeks, with millions of tokens of history behind a capped live window, and stays fast and on goal. The next tests add rules that must still hold at the end, procedures learned early, and a second seed at 32K. The problem, the model’s limits and the plan.

The practical difference

Files and archives store the records. Active context is what the model can use right now. In these tests, that active numerical state stayed in GPU memory. How tools bring saved information into the next prompt.
