What the context numbers mean

32K is the proxy’s working-view budget; about 215K was the full-history run’s largest prompt. The baseline server had 262,144-token capacity. Its history included prior reasoning, which ctxkeeper strips from the managed view. This accounted for most of the difference in total prompt traffic; notes, archiving and recall also ran. See the campaign 15 analysis.

The million-token ctxkeeper run used additional task-specific thinking and notes-check settings. These comparisons used the same server allocation and did not measure a reduction in VRAM use.

Release validation

One-card hardware result

On one 32 GB Intel Arc Pro B70, Qwen3.8-27B FP8 fixed 40/40 bugs, kept all rules and answered 7/7 questions in 21.1 minutes. This run used a 26,624-token total budget, with 8,192 tokens reserved for replies, and offloaded input embeddings to CPU memory. Its largest actual model request was about 14K tokens. It was not the default 32K setup. See the campaign 22b result.

The server’s reported cache-pool capacity is not a measured per-conversation VRAM footprint. This hybrid model has attention-cache and recurrent-state overhead that varies with server settings. We have not measured full-history VRAM requirements at 2M or 10M tokens, or concurrent-agent capacity. Equal advertised card memory does not establish equivalent runtime support or usable memory.

Published package checks

Version 1.2.0 was installed from the public release using the published installation steps, then ran the repair task (40/40, 7/7), the 300K demo through the Docker image (4/4), the SDK example (plain, tool call, streaming) and a 100K Gemma check (4/4) — lab campaign 50. One model, one machine; the notes are written by the model and can be wrong.
