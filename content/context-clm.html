CLM gives the model an editable conversation. Here CLM means Context Language Model: the model can replace obsolete parts of its live transcript with useful state, rather than only appending new messages.

For a ledger, the loop is simple: read a batch, update the totals with code, then replace the processed batch with a short state table.

How is that different from a summary or a plan file?

A periodic summary replaces a large portion of the conversation at a chosen threshold. CLM can make smaller, targeted edits: update a counter, delete a superseded log, or keep an exact quotation. In both cases, information removed without a saved copy is gone.

An ordinary plan file lives outside the live conversation. The model sees it when the application loads it. The CLM mirror is different: an accepted edit changes the message history sent on the next call. Merely saving a transcript file does not make this happen.

What did the experiment find?

With files forbidden, the original CLM agent returned 19/24 correct values in 64 minutes. A large-context baseline got 24/24 in 26 minutes; periodic summarization got 24/24 in 41 minutes.

The surrounding software discarded five batches after delivering them, and they could not be fetched again. That explains all five wrong answers. The model’s own state edits did not cause these misses.

Why not just delete old thinking?

The model may have stored its working state there. Removing earlier thinking left one run repeatedly rebuilding its state, without a final answer after 2.6 hours. Keep explicit task state before attempting this optimization.

How much room did earlier reasoning use?

A median 9.9% of input across 277 calls in the initial key-value comparison, reaching 55.8% on one call. The stuck trial was a separate large-window ledger run. Measurements and outcome.

Can a small CPU cleaner solve the problem?

Conservative cleanup removed 1.83% of roughly five million tokens. That is too little to turn a 32K window into 100K. Moving large outputs to files saved more visible space, but later questions can require reading them back. Cleanup measurements.

The revised agent and the larger-stream test

The revised harness protects delivered batches, checks room before fetching another, and keeps explicit state visible to the model. It checks the state's size and, optionally, format; those checks do not establish that every value is correct. It also supports removing old thinking while retaining that state. The published snapshot contains the implementation and stub checks, but no completed result for the revised agent or the proposed 480K-token stream.

Paper and wider research

The Context Language Models paper introduced this editable-context approach and evaluated it on other models and workloads. The lab’s key-value generator and running ledger are local experiments, not the paper’s released benchmark or a reproduction of its headline scores.
