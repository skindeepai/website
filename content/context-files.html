The big saving came from doing less work inside the model. Files let code keep the ledger up to date while the model worked with a short conversation. There was no need to reread or regenerate every record on every turn.

Does writing to disk slow decoding?

A file operation takes time, but it is a tool action between model calls. The model does not read every saved file for every output token. Its decode speed depends on the active context and the serving system, not simply on the size of the archive.

The trial measured the whole task, including tool use. It did not isolate the cost of writing a file or prove that disk access is free. The total was much lower: about 1.9 minutes with files versus 26 minutes with the large context and 41 with periodic summaries, all with 24 correct answers.

Generation fell from 89K tokens in the large-window run and 211K in the summary run to about 7–8K with files. Fewer generated tokens and a shorter active context both help; the task timings do not separate their individual contributions.

Is anything lost?

Saving the original text intact preserves those bytes. It does not guarantee that the model will find the right record, apply updates correctly or remember to search. Keeping only a table of current totals also discards the history unless that history is saved separately.

On this task, the current table was enough. For a question about why a value changed, or an exact quotation from an old document, the original records may be essential.

A real failure: saving only half a batch

In the earlier key-value comparison, all 12 trials moved data into files. Some used a shell pipeline that saved and displayed a batch at the same time. Stopping the display early also stopped the saving process, leaving truncated files. The resulting scores measured a file-saving failure, not a difference between context policies.

The practical lesson is to save the complete record first and preview it afterward. Preserve the original when later questions may need it. Read the original trial analysis.

When is this useful?

Logs, source trees, tables and document collections are good candidates when a tool can locate or compute the relevant information. Comparing themes across many documents may require reading more passages and several model calls. Files supply an archive, not simultaneous understanding of everything in it.
