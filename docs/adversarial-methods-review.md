# Adversarial review: research methods and remaining work

This September 2026 internal review inspected code and evidence for the shared BERT model, fresh-message evaluation, search, selective quantization, screenshot actions and practical demos. It recomputed retained artifacts; it did not independently rerun these models or establish production performance. The separate output-token experiments have their own review.

## Findings

- **No new arithmetic failure in the audited studies.** The compact-model audit passed 17 reported method paths; search passed 200 predictions and 3,000 recorded timings; selective quantization passed 192 records and all layer-state summaries; the visual audit passed 50 screenshots, 200 action decisions and 60 full/crop execution traces. The existing audit scripts were executed with result writes disabled, preserving their original artifacts.
- **The shared model's useful result is real within its test.** Its frozen rule preserved all 500 full-depth decisions and proposed 400 exits after layer 2. Actual execution and timing are separately tested on 50. The key remaining weakness is only 18 toxic examples in that fresh sample, not a discovered gate implementation error. The selected distillation candidate reduces false blocks but increases toxic misses; choosing a different seed because it looks better on this test would consume the holdout.
- **Search fusion remains the strongest tested search option.** The frozen combination wins 15 first results and loses one versus keywords. The optional reranker is a different tradeoff, not a demonstrated improvement over fusion. One exact training-text duplicate is already removed in the sensitivity analysis. The shortlist misses every judged relevant document on 29 of 200 queries, limiting any reranker.
- **The quantization and GUI failures are reported accurately.** Attention-only Qwen conversion preserves aggregate accuracy but changes four decisions on 32 development messages, including a new toxic miss. On the harder desktop sample, the click cutoff accepts only four present targets and gets two wrong. These should remain diagnostic candidates, not promoted results.
- **The practical privacy result needed a more useful error measure.** A new retrospective [span audit](privacy-spans.md) shows only 290/397 fully observed PERSON occurrences have every token marked. Another 48 occurrences cross or fall outside the processed prefix. This adds substantive error analysis without changing the primary website or the original token score.

## Work worth doing next

1. **Fresh moderation under a defined policy.** Freeze the existing shared checkpoint and stop rule; collect a separate adequately sized toxic challenge set alongside benign traffic. Include context-dependent abuse, split messages and long inputs. The current independent-message ToxicChat label is not Steve's full conversation-aware moderation policy. Measure added toxic misses and false blocks separately before choosing a replacement.
2. **Bring the matched readout comparison into the browser.** Existing browser Qwen paths use vocabulary scores; they do not execute the newly measured CPU two-row readout or a matched trained Qwen head. An export should compare identical backbone weights, precision and inputs, with checks of outputs and actual graph execution. This is implementation work, not solved by another explanatory paragraph.
3. **Whole-document name detection.** Evaluate contextual multi-token predictions and overlapping windows using the span failure analysis, including false masking. The current browser classifier is real, but its original 1,200-token boundary and PERSON-only target remain real functional limits.
4. **Improve search candidates before a larger reranker.** Evaluate the union of lexical and semantic shortlists and development-selected hard-negative training, then confirm on a new domain or held-out document families. Keep index construction separate from request cost.
5. **Train an explicit no-action option for screenshots.** Use development examples of infeasible requests and ambiguous targets; evaluate useful accepted-action coverage on untouched screenshots. A concentration cutoff cannot establish semantic feasibility. The lightweight OCR browser demo is a separate real implementation, not GUI-Actor running in the browser.

Receipts still need an OCR-inclusive test with merchant/template separation; routing still needs genuinely new unsupported intents. Existing live demos and stored replays are identified correctly in the inspected implementation and method notes. A clean-checkout experiment installer and physical Safari/iOS model testing also remain incomplete; neither invalidates the stored CPU/Chromium measurements.
